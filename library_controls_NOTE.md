# Library controls: rows 10 and 11

## Row 10: negative control for level mode

`jn_tail_corrupted.json` is identical to `jn_tail.json` except that the gamma-coefficient of the first fail atom of tool RS1 is shifted by +1/24, a transcription-slip-sized error rather than a mutation-sized one. `expected_profile` is unchanged, so the file must FAIL, and it does: certify.py reports a mismatch at every slice (e.g. gamma = 1 yields 11/48 against the expected 1/4) and exits 1. Both modes now have a FAILED exemplar, this one for level mode and `rs_pns_misquoted.json` for coverage mode.

The first corruption attempted was tool FI0, and that certificate PASSED. This is worth keeping in the record rather than hiding: the drop-FI-family ablation already documents that the FI tools are not needed for the optimum, so a corrupted coefficient inside certified slack is undetectable by construction. The selection note inside the instance file records this. It is the slack-census point in miniature, and it is the reason the negative control must corrupt a load-bearing coefficient, here RS1.

## Row 11: bracket slices for the mutation suite

Bracket slices are now installed systematically rather than ad hoc. For each coverage instance, every observable coverage boundary was located by exact interval scan over base and all ablation configurations, snapped to its exact rational, and bracketed by slices at distance 1/100 on whichever sides preserve the base expectation. The boundaries found were exactly the declared thresholds and ablation thresholds, plus the two-sided band edges, with no undeclared boundary anywhere, which is itself a check the library had not run before. All certificates pass with the enlarged slice sets: rs_pns 36/36, heath_brown 64/64, guo_guo_lu 76/76. Level-mode instances need no brackets, because every slice checks an exact profile equality and any profile shift kills at the slice itself.

Fresh mutation runs on the bracketed instances: rs_pns 16/64, heath_brown 12/48, guo_guo_lu 22/104. The kill rates are unchanged from the pre-bracket runs, and this is the row's actual result. Brackets convert a survivor to a kill only when the mutated atom's facet is observable in some checked configuration but happened to fall between slices. The one historical instance of that, heath_brown's complement ceiling before the 2201/2500 bracket, is now covered systematically. Every remaining survivor is an atom whose facet is unobservable in every configuration the instance checks: dominated by another fail option, masked by a stronger tool on the same piece, interior to certified slack, or movable only by amounts the 1/50 perturbation cannot achieve against the local facet spacing. The survivor set is therefore exactly what the census column says it should be, a certified-slack census, and the per-instance audit notes classify every survivor by hand.

One route to shrinking the survivor sets further exists and is deliberately not taken here: adding ablations that isolate individual fail options (for instance, removing every option of a tool except the dominated one) would make dominated facets observable. That changes what the instance asserts rather than how finely it is sliced, so it is an authorial decision per instance, not a harness default.
